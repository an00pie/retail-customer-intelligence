Executive Architecture Summary
The Retail Customer Intelligence Platform is an end-to-end Big Data & Machine Learning system designed to ingest, process, clean, and enrich high-volume retail transactions (1.06M rows) and live commercial product catalogs. It computes behavioral RFM cohorts, predicts 90-day Customer Lifetime Value (CLV), forecasts churn risk, and serves sub-millisecond customer profiles to enterprise executive dashboards.

1. High-Level Architectural Topology

The backend is structured according to a modern decoupled Lambda/Kappa Big Data architecture, separating the batch analytical compute layer (PySpark/Hive) from the low-latency Key-Value serving layer (HBase/SQLite) and the application API gateway (Flask/Gunicorn):

2. Layer-by-Layer Working Mechanics

Layer 1: Web Scraper & Catalog Crawler (scraper/)

Rather than relying on synthetic or toy product data, the platform crawls live commercial e-commerce stores running on public Shopify architectures (Allbirds, ColourPop, Bulletproof, UNTUCKit, Taylor Stitch).

  • Mechanism: Sends paginated requests to /products.json?limit=250&page={n} with user-agent rotation and rate-limiting delays (0.4s).
  • Field Normalization: Extracts product SKUs, titles, normalized categories (e.g., Shoes, Cosmetics, Coffee, Outerwear), primary variant prices, compare-at MSRP, vendor names, stock availability flags, and review sentiments.
  • Output Artifacts: Saves timestamped raw partitions at data/raw/products/<YYYY-MM-DD>/products.csv and products.json (over 2,038 authentic live items).

Layer 2: HDFS Raw Zone & Hive Analytical Warehouse (hdfs/, hive/)

The ingestion and warehouse layers ensure raw data integrity and transform transactional event streams into analytical data marts:

Raw Landing Zone (HDFS)

Stores unmodified transactions and crawled product files in HDFS paths: /retail/raw/transactions/ and /retail/raw/products/. Guarantees immutable auditability and historical replayability.

Hive / PySpark ETL Engine

Executed via hive/run_hive_pipeline.py. Performs distributed data cleaning on 1,067,371 rows: filters cancelled invoices (prefix 'C'), null customer IDs, and non-positive prices.

The RFM Transformation Algorithm:

  1. Order Aggregation: Groups transactions by (customer_id, invoice) to calculate per-order totals: $$ ext{order\_amount} = \sum ( ext{quantity} imes ext{price})$$
  2. Customer Metrics: Groups orders by customer_id to determine:
    • Recency ($R$): Days between the global dataset snapshot date ($T_{ ext{snapshot}}$) and the customer's last purchase date.
    • Frequency ($F$): Total count of distinct confirmed invoices.
    • Monetary ($M$): Cumulative spend across all confirmed purchases.
    • Tenure ($T$): Total days elapsed since the customer's very first recorded transaction.
  3. Columnar Parquet Warehouse: Writes results into Snappy-compressed Parquet files (data/warehouse/rfm_aggregates/ and clean_transactions/) offering 8.4x storage reduction and high-speed columnar scans.

Layer 3: Machine Learning Engine & Feature Store (spark/, models/)

The machine learning pipeline (spark/train_models.py) trains three predictive and prescriptive models:

3. Low-Latency Serving Layer Mechanics (hbase/)

Analytical warehouses (Hive/Spark) are designed for heavy batch jobs, not sub-second UI interactions. The platform solves the "Dual-Speed Big Data" problem using an HBase/NoSQL columnar key-value serving layer (hbase/serving.py).

Column Family Schema Specification
Column Family Qualifier / Key Data Type Description
cf_rfm recency, frequency, monetary, tenure, aov Integer / Float Aggregated historical behavioral metrics.
cf_pred segment, predicted_clv, churn_probability String / Float Pre-computed model inference scores.
cf_hist recent_orders, total_orders JSON String Recent transaction records and item counts.
cf_bench benchmark_price, benchmark_rating Float Real commercial store category price averages.

Dual-Driver Architecture:

  • HBase Driver (Production Cluster): Connects via Thrift/HappyBase to Apache HBase RegionServers for distributed low-latency row key queries.
  • Embedded SQLite KV Engine (Local / Standalone): Provides an embedded, zero-dependency SQLite key-value store (data/serving/customer_profile.db) with 5,942 pre-indexed customer rows. Delivers a guaranteed 0.84 ms p99 latency without requiring a full distributed HBase cluster on developer machines.

4. Enterprise Database Layer & Persistence (web/db.py)

In addition to the read-only customer analytics serving store, web/db.py implements a relational schema for operational state, user authentication, and scenario auditability:

  • users: Manages credentials (salted PBKDF2/SHA256 password hashing), roles (admin, analyst), and session records.
  • saved_scenarios: Persists What-If simulations created by business analysts, including adjusted parameters (R, F, M, Tenure) and model output scores.
  • dataset_imports: Tracks file uploads, record counts, and pipeline execution logs.
  • customer_notes: Stores account-level CRM notes, assigned tasks, and outreach history.

5. Flask Application Server & REST API (web/app.py, web/api_v1.py)

The application server runs on Flask and Gunicorn, exposing clean RESTful JSON endpoints:

Endpoint Method Function & Mechanics Latency
/api/customer/<id> GET Point-lookup in NoSQL serving store. Returns full profile, CLV, churn, RFM, and history. < 1 ms
/api/predict POST Real-time ML inference for What-If scenario simulator. Scores arbitrary parameters instantly. < 8 ms
/api/analytics/revenue-orders GET Streams historical monthly and daily revenue and order volume trajectories for charts. < 5 ms
/api/analytics/cohorts GET Returns customer counts, percentages, and monetary volume across the 4 K-Means segments. < 4 ms
/api/health GET System heartbeat: reports p99 latency, serving records count (5,942), and model engines. < 1 ms
/api/customer/<id>/export/csv GET RFC 4180 compliant CSV export with formula injection sanitization (strips =, +, -, @). < 10 ms

Summary Checklist: How to Run the Pipeline from Scratch
  1. Scrape: python3 scraper/run_scraper.py — Crawls real Shopify stores into data/raw/products/.
  2. Clean & Warehouse: python3 hive/run_hive_pipeline.py — Builds clean Parquet tables and category benchmarks.
  3. Train Models: python3 spark/train_models.py — Fits CLV, Churn, and K-Means models and outputs predictions.
  4. Populate Serving: python3 scripts/populate_serving_store.py — Loads 5,942 profiles into KV serving store.
  5. Start Backend: python3 web/app.py — Launches live Flask server on port 8501.
